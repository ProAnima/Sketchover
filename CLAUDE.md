# Sketchover — правила проекта

Десктопный оверлей для рисования поверх окон. **Tauri 2**: процесс ОС на Rust (`src-tauri/`), интерфейс — ванильный JS в ES-модулях без сборки и фреймворков (`src/`). Windows / macOS / Linux.

Главный критерий любого решения: **самое простое, что решает задачу**. Если можно не добавлять — не добавляй.

План фич и ключевые технические решения — в [docs/ROADMAP.md](docs/ROADMAP.md). Новую фичу сверяй с ним; меняется решение — обнови документ. Образец для обновлений, «О программе» и локализации — Signal Lab (`../pas-SignalLab`).

## Принципы

### Простота (KISS / YAGNI)
- Не добавляй абстракции, настройки, слои и зависимости «на будущее». Три похожие строки лучше преждевременной обёртки.
- Новая зависимость (npm или crate) — только если без неё заметно сложнее и она маленькая, поддерживаемая и без лишних транзитивных пакетов. Сначала проверь Web API, Tauri и официальные плагины `tauri-plugin-*`.
- Без сборщиков, TypeScript и фреймворков, пока пользователь явно не решит иначе.
- Комментарий объясняет **почему**, а не что. Не комментируй очевидное.

### SOLID — в меру, применительно к JS-модулям
- **S**: один модуль — одна причина для изменения. Файл больше ~300 строк или с несколькими ответственностями — разбивай (рендер холста, инструменты, история undo/redo, панель UI, ввод — отдельно).
- **O**: новый инструмент добавляется новым модулем/записью в реестре инструментов, а не ещё одной веткой `if/switch` в общем коде.
- **L**: все инструменты имеют единый интерфейс (`down`, `move`, `up` + метаданные `id`, `label`, `icon`/`iconPath`); подменяемы без правок вызывающего кода. Рисуют фигуры не инструменты, а `ui/canvas.js`.
- **I**: модуль получает только то, что ему нужно (узкие аргументы/колбэки), а не весь `state`.
- **D**: логика зависит от маленьких интерфейсов, а не от Tauri/DOM напрямую. Доступ к ОС — только через `src/ui/api.js` (команды и события Tauri). Чистая логика (геометрия, история, фигуры) не трогает DOM и Tauri и покрыта тестами (`tests/`, `node:test`, без зависимостей).

### Зависимости между слоями (строго вниз, без циклов)
```
src-tauri/ (Rust: окно, сквозные клики, трей, хоткей, настройки, снимок экрана, файлы и буфер, обновления, статистика)  ←команды/события→  src/ui/api.js
src/ui/     холст, панель, настройки, ввод, режимы (верхний слой)
src/tools/  инструменты с единым интерфейсом down/move/up
src/core/   состояние, фигуры, геометрия, история, Markdown, картинки, формат файла (чистая логика)
src/i18n/   словари; используется только из ui
```
- Инструмент получает от UI только `host = { render, edit }` — так `tools` не импортирует `ui`.
- Измерение текста подставляется в `core` через `setTextMeasurer` — `core` не знает про canvas.
- `core` не импортирует `tools`/`ui`; `tools` не импортирует `ui`. Циклических импортов нет.
- Общее состояние — в одном месте (`core/state.js`), мутации через явные функции.
- Rust-сторона ничего не знает о рисовании; интерфейс ничего не знает об окнах ОС.
- В Rust: один модуль — одна ответственность (`overlay`, `keys`, `hotkey`, `tray`, `settings`, `capture`, `files`, `updates`, `stats`), команды — тонкие обёртки в `lib.rs`.
- Окно трогаем только из главного потока: фоновые потоки лишь ставят задачи (`run_on_main_thread`) и не ждут их, замки не держат через вызовы окна — иначе взаимная блокировка.

## Безопасность (Tauri)
- Capabilities — минимальные (`src-tauri/capabilities/default.json`): только то, что реально вызывает интерфейс. Плагины, нужные лишь Rust-стороне, интерфейсу не открываются.
- Каждая команда проверяет входные данные (тип, диапазон, список допустимых значений); интерфейсу не доверяем.
- Строгий CSP в `tauri.conf.json` (`default-src 'self'`, без inline-скриптов и стилей). Стили из JS — только через CSSOM (`el.style.x = …`), не атрибутом.
- Не использовать `eval`, `new Function`, `innerHTML` с данными — только `textContent`/`createElement`.
- Сеть — только обновления через хаб (и запасной GitHub) и анонимная статистика в хаб (выключается в настройках). Подпись каждого обновления проверяется ключом из конфига; приватный ключ — только в CI, никогда в репозитории.
- На диск пишем только настройки в каталоге конфигурации приложения, запись автозапуска средствами системы и файлы, которые человек сам выбрал в системном диалоге (путь интерфейс не задаёт). Битые настройки → значения по умолчанию, не падение.
- Открываемые файлы — недоверенные: сцену проверяет `core/scene.js` (известные фигуры, корректные поля), размер файла ограничен.
- Ничего личного наружу: в хаб уходит только случайный `install_id`.
- Перед релизом: `cargo clippy -- -D warnings`, `npm audit`, актуальные Tauri и плагины.

## Кроссплатформенность (ПК: Windows, macOS, Linux)
- Пути в Rust — `PathBuf`/`join` и каталоги из `app.path()`, никаких разделителей вручную.
- Глобальный хоткей — в формате Tauri (`Alt+Backquote`, `CommandOrControl+…`); регистрация может не удаться (комбинацию держит другая программа) — не падаем, оставляем прежний и показываем в настройках.
- Платформенные особенности окна (прозрачность, поверх всех, все рабочие столы, сквозные клики) — только в `src-tauri/src/overlay.rs`, с комментарием о причине.
- Мониторы и DPI: размеры не хардкодить; холст открывается на мониторе с курсором; в Rust переводим физические пиксели в CSS через `scale_factor`.
- Скрипты `package.json` — без shell-специфики.
- Окончания строк — LF (`.gitattributes`/`.editorconfig`).

## Производительность
- Рисование — `requestAnimationFrame`, перерисовка только при изменении (dirty-флаг), не по таймеру.
- Не аллоцируй объекты в горячем пути `pointermove`; для карандаша — упрощение точек, ограничение размера истории.
- Перерисовка склеивается в один кадр (`render()` → `requestAnimationFrame`); при росте нагрузки разнеси статику и динамику (штрих, лазер) по разным canvas.
- Учитывай `devicePixelRatio`; не делай ресайз канваса на каждый кадр.
- Слушатели и таймеры снимай, когда они не нужны (в режиме сквозных кликов приложение должно простаивать почти без нагрузки CPU).
- Ничего тяжёлого в главном потоке Rust; фоновые потоки спят, когда не нужны (опрос `Alt` и курсора — только пока холст виден).

## Простота использования (UX)
- Работает «из коробки»: запустил — рисуй. Минимум настроек, разумные значения по умолчанию.
- Каждое действие доступно и мышью, и горячей клавишей. Глобальный хоткей — **один** (по умолчанию `` Alt+` ``, переназначаемый); не больше 2–3 клавиш в комбинации. Внутри холста: цифры — инструменты, `Alt+цифра` — цвет, `Shift+цифра` — толщина, зажатый `Alt` — мышь окнам под холстом, двойной тап `Alt` — сквозной режим вкл/выкл.
- Клавиши определяем по `e.code` (физическая клавиша), не по `e.key`: иначе ломаются раскладки и модификаторы.
- Новый хоткей — сразу в памятку (`ui/help.js`) и README.
- Состояние режима (рисование / сквозные клики) всегда явно видно на экране.
- Панель не должна перекрывать работу и должна оставаться кликабельной в сквозном режиме.
- Настройки и «О программе» — одна компактная раскрываемая панель, не отдельные окна.
- Все тексты интерфейса — через `t(key)`, 11 языков как в Signal Lab; новый ключ добавляется во все словари. README.md и CHANGELOG.md — на английском (поиск, страница релиза), README.ru.md — полная русская версия, остальные документы — на русском; новая версия — раздел в CHANGELOG.md (из него берутся заметки релиза); изменил поведение или горячую клавишу — обнови оба README.

## Стиль кода
- JS: ES-модули, `const` по умолчанию, `let` при необходимости, без `var`.
- Маленькие функции с говорящими именами; ранние `return` вместо глубокой вложенности.
- Ошибки не глотать молча; обрабатывать на границах (IPC, ввод пользователя).
- Мёртвый код, `console.log` для отладки и закомментированные куски не коммитить.
- JS: 2 пробела, одинарные кавычки, точки с запятой. Rust: `cargo fmt`, без `unwrap()` на данных извне.

## Git и процесс
- Коммиты небольшие и атомарные, формат `feat: ...`, `fix: ...`, `refactor: ...`, `docs: ...` (описание на русском, как в истории).
- Рефакторинг отдельно от изменения поведения.
- Перед коммитом: `npm run check`, `npm test`, `cargo fmt`, `cargo clippy --all-targets -- -D warnings` и `cargo test` чистые; `npm start` запускается, основные сценарии (рисование, сквозной режим, хоткей, настройки) проверены вручную. Это же гоняет CI.
- Основная ветка — `main`.
